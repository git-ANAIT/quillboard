# Quillboard — the offline AI keyboard

A free Android keyboard that corrects English and rewrites it in a chosen tone, entirely
on the phone. No `INTERNET` permission, no login, no ads, no paywall, no cloud.

**Developed by Clear Theory** · version 1.0.0 · Apache-2.0

This repository is the whole product: the Android app, the engine, the language-pack
pipeline that builds its data, the test suites, the store listing text, and a working
browser prototype of the same engine you can open in any tab.

1. **It has not been run on a phone or emulator.** This workspace has no KVM acceleration
   and no screen, so the APK is verified statically and by the 84 + 21 test suites, but it
   still needs one real-device pass (the checklist in `docs/RELEASE.md`). It is also not
   minified here — R8 wants ~2 GB of heap and this machine has 1 GB; CI runs the minified
   build (`-Pquillboard.minify=true`).
2. **No model file ships.** Tier B (the optional on-device LLM) is a complete interface
   with a RAM gate and a guaranteed fallback to the rule engine, but the 0.4–1.2 GB of
   weights are an import, not a download — there is no network to download them with.

## 1. Try it

Open **`demo/index.html`**. Screenshots of it live in `docs/screenshots/`. It is one file: engine, language data and UI inlined, no
network code at all (the page counts requests and shows zero).

Things worth doing:

- Type `teh` and press **space** → `the`, with `↺ teh` in the strip to restore it.
  `definately`, `recieve`, `seperate` all go the same way — see §3 for why that is harder
  than it looks.
- Type `i would like to discuss about the project` and tap **Professional** → the rewrite
  drops `about`, capitalises `I`, and fixes the spelling in the same pass.
- Tap **Academic** or **Casual** on the same sentence → different registers from the same
  rules, with the panel on the right listing every swap and every grammar fix applied.
- Press **Undo** → the original comes back exactly, character for character.
- Switch to the **Password** or **Search / URL** tab → corrections switch off and the tone
  bar disappears, because those fields are never read.
- Open the emoji key → an emoji page; in the Android app, long-pressing it opens the
  clipboard page.

The reference implementation the prototype runs is logic-identical to the Kotlin engine:
same layers, same thresholds, same phrase tables. The prototype ships a 25k-word
frequency dictionary plus the 80k-word "known" set to keep the file small; the app ships
the full pack.

### Rebuilding the language pack

```bash
./tools/fetch_data.sh                                    # upstream word lists + corpus
CORPUS_DIR=.corpus python3 tools/build_language_data.py   # → app/src/main/assets/, demo/langpack.js
node tools/export_typos.js                                # engine typos → data-src/typo_blocklist.txt
python3 tools/build_demo.py                               # → demo/index.html
```

`build_language_data.py` caps everything (`KNOWN_WORDS_MAX = 200_000`,
`CORRECTION_INDEX_SIZE = 80_000`, `MAX_BIGRAMS = 150_000`, `MAX_TRIGRAMS = 100_000`) so the
APK stays around 3.3 MB of compressed data on every machine that runs it.

## 2. Build the Android app

```bash
./gradlew :app:assembleDebug                                  # debug APK
./gradlew :app:assembleRelease                                # signed release (needs keystore.properties)
./gradlew :app:assembleRelease -Pquillboard.minify=true       # minified, for a store build
```

The wrapper is committed, so a fresh clone builds with just a JDK 17 and the Android SDK
(`ANDROID_HOME`, or `local.properties` with `sdk.dir`). Everything except minification
builds in about 1 GB of RAM; R8 needs ~2 GB.

Then: install, enable *Quillboard* in system keyboard settings, and switch to it. The app
opens on a first-run screen, then Settings — theme, key height, haptic strength, tone-bar
visibility, personal dictionary, engine statistics, About.

Requirements: `minSdk 26`, `targetSdk 35`, Kotlin 2.0, Coroutines, Room (KSP). Dependencies
are four libraries — Room runtime/compiler, coroutines, and the AndroidX annotation
library. There is no network library in the dependency graph, because there is no network.

## 3. How the engine works

Five layers, in the order they run on every keystroke and every rewrite.

**Layer 1 — spelling.** SymSpell (max edit distance 2, 7-character prefix) over the 80k
most frequent English words, with every candidate re-scored by a QWERTY-aware typo model,
unigram frequency, and bigram context. Per keystroke: well under a millisecond.

**Layer 2 — context.** 150k bigrams and 100k trigrams from 4.7M tokens of public-domain
prose, with precomputed next-word buckets so prediction is a map lookup plus a sort of at
most eight candidates. This is what makes *their*/*there* and *its*/*it's* decisions
contextual rather than frequency-only.

**Layer 3 — grammar.** 45 deterministic rules: a/an (with vowel-sound exceptions like
*an hour*, *a university*), subject-verb agreement, doubled words, lowercase `i`, sentence
capitalisation, day/month capitalisation, `its`/`it's`, `your`/`you're`,
`there`/`their`/`they're`, `then`/`than`, `to`/`too`, auxiliary agreement, spacing and
punctuation. Rules are ordered and idempotent; every applied rule is reported to the UI.

**Layer 4 — tone.** 286 phrase rules across three registers (Professional 87,
Academic 114, Casual 85), applied on top of a full Layer 1–3 pass so a tone rewrite never
returns text with a spelling mistake in it. Rewriting targets the selection, else the
sentence under the caret, else the paragraph. Undo restores the exact original until the
next rewrite.

**Layer 5 — learning.** Adding a word ("sumbal", "humhama") teaches the personal
dictionary and suppresses corrections for it on the spot; a long-press on a suggestion
removes it again. Stored in Room, editable and clearable in Settings.

### Why the dictionary has a "known" set and a separate frequency index

A frequency list only covers the head of the distribution, so a 25k dictionary thinks
*swamped* is a typo and "fixes" it to *stamped*. Quillboard therefore ships two lists:
a 200k-word **known** set that decides what counts as a word at all, and an 80k-word
**correction index** (with counts) that proposes candidates. Real words are never
"corrected"; typos still are.

Building that known set surfaced the opposite trap. Web-frequency corpora contain the
misspellings themselves, with enormous counts — `teh` (1.69M), `definately` (1.73M),
`recieve` (1.40M) all rank above most real words. Dropped into a dictionary unchanged,
they make the keyboard *stop* fixing the most common typos in English. Two guards:

- `tools/export_typos.js` exports the engine's canonical misspelling list to
  `data-src/typo_blocklist.txt` (175 words), and the pack builder removes them first.
- Any remaining word under 1,000 in frequency that sits one edit away from a word at least
  100× more frequent is treated as a misspelling and dropped (74,743 removed).

The engine also checks the canonical list *before* the dictionary, so a typo can never win
by frequency alone.

## 4. Tests

```bash
npm install                      # jsdom, for the prototype suite
npm test                         # both suites
node tools/test_engine.js        # 84 assertions: correction, grammar, tone, undo, latency
node tools/ui_test.js            # 21 assertions: the actual prototype DOM, in jsdom
```

Covered: the 20 most common misspellings, real-word confusion pairs, a/an including vowel
sounds, doubled words, capitalisation, all three tones, undo fidelity, the "Layer 1 runs
inside a tone rewrite" invariant, password/email/URL suppression, and a network-request
counter that must stay at zero.

Latency from the reference implementation (this laptop, single core):

| Operation | Per call |
| --- | --- |
| `correct("recieve")` | 0.001 ms |
| `suggest("meet")` | 0.34 ms |
| `predictNext(3 words)` | 0.87 ms |
| grammar pass, 1 sentence | 0.06 ms |
| Professional rewrite | 0.13 ms |


secrets.

### RAM tiers

The correction index is a hash of deletes, so its size scales with the word count. The
suggested index for each tier is chosen at startup from `ActivityManager.memoryClass`:

| Tier | Device RAM | Correction index | Bigrams | Trigrams | Deletes | Rough index size |
| --- | --- | --- | --- | --- | --- | --- |
| `FULL` | ≥ 5.5 GB | 80,000 | 150,000 | 100,000 | 659,488 | ~73 MB |
| `BALANCED` | ≥ 3.5 GB | 50,000 | 100,000 | 60,000 | 443,831 | ~49 MB |
| `COMPACT` | else | 25,000 | 60,000 | 30,000 | 245,924 | ~27 MB |

The known set (200k words, ~1.4 MB on disk) loads in every tier — it is the cheap part.

## 5. Privacy

- **No `INTERNET` permission.** Not "we don't send data" — the system makes it impossible.
  `grep -c uses-permission app/src/main/AndroidManifest.xml` prints `0`.
- **Never read, never rewritten:** password fields, email fields, URL fields, phone
  numbers, and any field the system marks as sensitive. The tone bar hides itself, the
  suggestion strip says why, and no text is copied anywhere into memory we keep.
- **Stored on the phone:** personal dictionary, pinned clips, settings, emoji recents.
  All visible and deletable in Settings; cloud backup is off (`allowBackup="false"`).
- **No logging of typed text** in release builds; no analytics, no account, no ads.
- The optional Tier B model runs locally from a file you import, and its output never
  leaves the device either.

Full policy: `docs/PRIVACY.md`. Data provenance: `docs/DATA_LICENSES.md`.

## 7. What is deliberately not done

- **No APK in the repo** — no SDK here (see the caveat at the top).
- **No model weights** — Tier B is plumbing plus a fallback, not a shipped LLM.
- **No iOS app** — the plan puts it later; platform restrictions make a third-party
  keyboard with these guarantees a different project.
- **No language beyond English.** The pack builder is corpus-driven, so a second language
  is a data exercise, not a rewrite — but it has not been done.
- **No website/contact filled in.** `Brand.WEBSITE` and `Brand.CONTACT_EMAIL` are
  `*.example` placeholders; the About screen and store listing will show them as-is until
  Clear Theory puts real values in one file (`Brand.kt`). `Brand.OTHER_APPS` is empty and
  the About screen hides the section; add the studio's other apps there and it appears.
